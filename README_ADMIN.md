# Руководство администратора Millex

## 1. Как устроен каталог

Публичный каталог сайта читает legacy-таблицы PostgreSQL `categories` и `items`:

- игры берутся из `categories` с `vis = 1` и `parent = 0`;
- чит относится к игре через JSON в `items."categoryData"`;
- alias чита используется в URL `/item/{alias}` и должен совпадать с alias ключа в Telegram-боте;
- периоды хранятся в `items.tabs`, цены — в `items.prices`, элементы массивов сопоставляются по индексу;
- цены каталога берутся из `items.price`.

Новая форма админки создаёт записи именно в `items`, а не в отдельной новой ORM-таблице `products`.

## 2. Добавить чит

1. Войди на сайт администратором и открой `/admin/products`.
2. Нажми «Добавить чит».
3. Укажи название, уникальный alias, игру, системы, описание и инструкцию.
4. Добавь каждый тариф отдельной строкой: подпись периода и цена. Например: `1 day` / `299`, `7 days` / `699`, `30 days` / `1399`.
5. Если нужны скриншоты или видео, добавь их в галерею (инструкции ниже).
6. Сохрани запись.

Форма записывает выбранную категорию в `categoryData`, периоды в `tabs`, цены в `prices`, минимальную цену в `price`. Даты на сайте форматируются по-русски: `1 день`, `2 дня`, `5 дней`, `21 день`.

Alias создавай строчными латинскими буквами, цифрами, `_` или `-`, например `sample_cheat_eft`. После создания alias нельзя менять без обновления URL, ключей и связанных заказов.

### Проверить созданный чит

Открой страницу товара `/item/{alias}`. API деталей:

```text
GET /api/catalog/items/{alias}
```

В ответе должны быть `name`, `alias`, `game_title` и непустой массив `tariffs` с ценами. Страница игры находится по `/catalog/{game-alias}`; её счётчик предложений должен увеличиться.

### Добавить собственное MP4-видео

Для видео товара можно хранить MP4 на сервере и вставлять HTTPS-ссылку своего домена. Это удобно для небольших промороликов: не нужно зависеть от настроек встраивания стороннего видеохостинга. Учитывай, что трафик и место хранения будут расходовать ресурсы сервера.

1. Docker Compose монтирует `/var/lib/millex/uploads` на сервере в `/app/uploads` контейнера backend. Создай каталог `/var/lib/millex/uploads/videos/`; не заменяй этот volume на каталог внутри `frontend`.
2. В форме `/admin/products` добавь элемент галереи типа «Видео» и нажми «Добавить видео». После загрузки ссылка на сохранённый файл подставится автоматически.
3. Допустимый размер видео — до 500 МБ. Backend собирает загруженные части непосредственно в `/app/uploads/videos/`, что соответствует `/var/lib/millex/uploads/videos/` на сервере.
4. Нажми «Сохранить» в форме товара, чтобы записать новую ссылку в галерею чита и показать ролик на его странице.
5. Проверь, что подставленный адрес открывается без авторизации по HTTPS и отдаёт `Content-Type: video/mp4`. При перемотке nginx должен отвечать `206 Partial Content` на запрос с заголовком `Range`.

В production `millex.market.nginx.conf` раздаёт видео из `/var/lib/millex/uploads/videos/` напрямую nginx-ом. Поддерживаются URL `/uploads/videos/demo.mp4` и старый короткий вариант `/uploads/demo.mp4`; оба соответствуют одному файлу в `videos/`. Админка передаёт файл отдельными порциями по 512 КиБ, а backend собирает их в видео размером до 500 МиБ — это работает и при стандартном лимите nginx в 1 МБ. `client_max_body_size 510m` в nginx-конфиге оставлен как дополнительный предел для API-запросов. Nginx не должен возвращать HTML главной страницы, если видеофайл отсутствует (в этом случае должен быть 404); остальные `/uploads/` по-прежнему обслуживаются backend. После установки обновлённого конфига проверь nginx через `nginx -t` и перезагрузи его. Используй MP4 с видео H.264 и аудио AAC; для быстрого старта/перемотки при экспорте включи опцию «Fast Start» (перенос метаданных MP4 в начало файла). Для локальной разработки Vite проксирует `/uploads/` в backend.

## 3. Управлять играми

Открой `/admin/games`: игры создаются и редактируются в legacy-таблице `categories` как корневые категории (`parent = 0`). Alias должен быть уникальным и состоять из строчных латинских букв, цифр, `_` или `-`. Можно задавать порядок и ссылку на изображение.

Кнопка «Скрыть» выставляет `vis = 0`, не удаляя товары и заказы игры; «Показать» возвращает `vis = 1`. Перед переименованием slug проверь ссылки на игру и связанные товары.

## 4. Загрузить ключи для автовыдачи

1. Открой `/admin/products` и нажми «Ключи» у нужного товара.
2. Загрузи текстовый `.txt` или вставь ключи в поле — по одному на строку, не более 5000 за раз.
3. Проверь счётчики свободных и выданных ключей. Уже загруженные ключи и повторения в файле будут пропущены.

Ключи сохраняются в таблице `keys` и привязываются к точному alias товара. Их можно также добавлять по одному через Telegram-бота: `/admin` → «Добавить ключ».

## 5. Заказ и выдача

При покупке с баланса и после успешного callback Platega backend автоматически резервирует свободный ключ и завершает заказ. Покупатель увидит выданный ключ на странице доставки. Если свободных ключей нет, заказ попадает в очередь Telegram-бота для ручной выдачи.

Из уведомления администратор может выбрать «Попробовать со склада» или «Вписать ключ вручную». Ручная выдача сохраняет введённое значение в `bot_orders.key_value`; заказ получает статус `completed`.

Проверить запись, не выводя секрет ключа:

```sql
SELECT external_order_id, item_alias, status,
       notification_sent_at,
       key_value IS NOT NULL AS key_saved,
       length(key_value) AS key_length
FROM bot_orders
ORDER BY id DESC
LIMIT 10;
```

Тестируй в staging или на тестовом товаре. Реальная оплата Platega может списать деньги. В текущем проекте уведомление о продаже приходит администраторам в Telegram; автоматическая отправка ключа покупателю по email не реализована.

## 6. Проверка нового товара без покупки

1. Создай тестовый товар через `/admin/products` с уникальным alias.
2. Проверь `GET /api/catalog/items/{alias}` и наличие тарифов.
3. Открой `/catalog/{game-alias}` и убедись, что товар отображается в списке.
4. Проверь `/item/{alias}`, изображение игры и формат периодов.
5. Удали тестовый товар штатным администратором БД после проверки; не удаляй строки production-заказов или ключей.

Для проверки оплаты используй только согласованный тестовый режим платёжного провайдера. Не проверяй живой платёж случайным production-заказом.

## 8. Заказы в админке

Открой `/admin/orders`. Список объединяет заказы из `orders` (магазин) и `bot_orders` (каталог/аккаунты), поддерживает поиск, фильтр статуса и выбор источника. Выдача товара продолжает выполняться существующим процессом оплаты и bot-worker; изменение статуса вручную в интерфейсе не предусмотрено.

## 9. Выплаты

Открой `/admin/payouts` для ручной выплаты на рублёвую карту через Platega. Отправка формы инициирует реальный перевод; USDT-выплаты не поддерживаются. Backend хранит сумму, последние четыре цифры карты, результат и ID провайдера в `admin_payouts`, но не сохраняет полный номер карты.

Если статус выплаты стал «Требует проверки у Platega» или запрос завершился неизвестным результатом, сначала проверь операцию у провайдера и не отправляй её повторно. В интерфейсе нет проверки доступного баланса Platega; убедись в наличии средств и корректности payout-доступа до подтверждения.

## 7. Выдача аккаунтов через NFA Resell API

Выдача аккаунта выполняется backend-ом через `POST /api/v1/activate_direct`: тип берётся из `accounts.alias`, а полученный EXE сохраняется в заказ и становится доступен покупателю из истории. Файл не загружается в таблицу `keys`.

Задай `NFA_API_KEY` в `backend/.env` на сервере и пересоздай backend-контейнер после изменения. Не помещай этот ключ во frontend, БД товаров или git. Перед покупкой проверь, что alias и локальный `accounts.meta_data.stock` соответствуют настроенному типу и остатку поставщика. Nginx для `/api/accounts/` должен использовать `proxy_read_timeout` и `proxy_send_timeout` не менее 240 секунд; устанавливай обновлённый конфиг и проверяй его командой `nginx -t` до reload.

Для обычных лицензий/ключей от авторизованного поставщика интеграция должна проходить только через backend, связывать заказ с provider transaction id, подтверждать оплату webhook-ом, защищаться от повторов и хранить только выданный license key. Перед запуском нужны письменное разрешение поставщика и отдельный тестовый контур.
